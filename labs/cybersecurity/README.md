# Cybersecurity and Digital Forensics Labs

A structured learning roadmap for defensive security, packet analysis, Linux security tools, and digital forensics.

> **Status:** Starter guide. These are suggested exercises, not claims of completed investigations or certifications. Add your own screenshots, commands, findings, and conclusions after performing each lab.

## Lab roadmap

| Tool / area | Exercise | Evidence to save |
|---|---|---|
| Wireshark | Inspect DNS, TCP handshakes, and HTTP traffic in a sample capture | Display filters and annotated packet screenshots |
| Kali Linux | Explore Linux networking and security utilities in an isolated virtual lab | Commands used and sanitized output |
| Autopsy | Examine a training disk image and identify files and metadata | Case notes and screenshots |
| FTK Imager | Create or inspect a forensic image of authorized media | Acquisition details and hash verification |
| Incident analysis | Build a short timeline from provided sample evidence | Timeline, observations, and limitations |

## 1. Wireshark packet analysis

Use a sample capture file or traffic generated by your own lab.

Useful display filters:

```text
dns
tcp
tcp.flags.syn == 1
http
icmp
```

Suggested workflow:

1. Open the capture in Wireshark.
2. Identify the endpoints and protocols.
3. Inspect a TCP three-way handshake.
4. Review DNS queries and responses.
5. Record unusual or noteworthy observations without assuming that an anomaly proves malicious activity.
6. Export only permitted sample evidence and redact sensitive information.

## 2. Kali Linux isolated lab

Run Kali Linux in a virtual machine on a host-only or otherwise isolated network. Use only systems you own or have explicit permission to assess.

Basic environment checks:

```bash
whoami
ip addr
ip route
ss -tulpen
ping -c 4 <your-lab-gateway>
```

Document the VM configuration, network mode, commands, expected result, and actual result. Do not scan public or third-party systems without authorization.

## 3. Autopsy digital forensics

Use a publicly available training image or an image you are authorized to examine.

Suggested workflow:

1. Create a new case and record its purpose.
2. Add the training disk image as a data source.
3. Allow ingest modules to process the evidence.
4. Review file system contents, metadata, deleted-file results, and timeline information.
5. Record findings with paths and timestamps.
6. State limitations and avoid conclusions that the evidence does not support.

## 4. FTK Imager and evidence integrity

For authorized media or a training image:

- Record the source description and acquisition date.
- Use a write blocker where appropriate for physical media.
- Create an image using a suitable forensic format.
- Calculate and record cryptographic hashes.
- Verify the image and preserve the original evidence.
- Keep a basic chain-of-custody record.

Never publish private files, personal data, credentials, or unredacted evidence.

## Report template

For each completed lab, add a report containing:

- **Objective:** What question did the lab address?
- **Environment:** Tool versions, VM settings, and sample source.
- **Method:** Steps and commands performed.
- **Observations:** What the evidence actually showed.
- **Conclusion:** What can and cannot be concluded.
- **Evidence:** Redacted screenshots, hashes, and sample outputs.
- **References:** Official tool documentation and relevant learning resources.

## Scope and ethics

All exercises must remain within an isolated lab, a supplied training dataset, or systems for which you have explicit authorization. Do not upload secrets, personal data, or sensitive forensic artifacts to this public repository.
